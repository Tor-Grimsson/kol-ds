## W1 — The identity set in kol-icons

### 1.1 — A folder per identity, one rule for the files — ✅ built 2026-10-28 (P: *"would it be a space?"*, *"just find a way to differentiate … suggest something"*)
- `kol-icon-set-identity/<id>/`, flat — the studio and every app the same way: `kolkrabbi/` · `kol-ds/` (KDS) · `mirror/` · `fxr/` · `monitor/` · `metric/` · `web/`… The `apps/` and `kolkrabbi/` sub-grouping goes; the gallery's groups come from the set's meta, not the folder.
- **The file named like its folder is the icon**: `mirror/mirror.svg` sits on the 24 keyline and is what `<Icon name="mirror">` renders — the one file the Icon map takes (the glob becomes `<id>/<id>.svg`), so Icon names do not change. Everything else in the folder is an asset by path, named by its role: `<id>-logomark.svg` (the raw mark in its own box, for `VectorLoader`, the boot loader and lockups) · `<id>-wordmark.svg` · `<id>-lockup-h.svg` · `<id>-lockup-v.svg` (his names) · `<id>-favicon.svg` (the tab icon, scheme `<style>` baked in) · `<id>-tile.svg` · the rendered PNGs (1.2) beside them.
- `<id>-tile.svg` is the touch icon as a vector: the logomark on the `#121215` ground at the 60 % rule in a 24 box — what Mirror ships today as `public/touch-icons/apple-touch-icon-dark.svg`. It is the thing reviewed on the Family row, and the 180 · 192 · 512 PNGs are rendered from it; the renderer writes it, nobody draws it.
- The studio's marks move in from kol-brand (`kol-logomark` · `kol-wordmark` · `kol-lockup-hori` → `-lockup-h` · `kol-lockup-vert` → `-lockup-v` · `favicon-01` · `favicon-kolkrabbi` · `favicon-kol-ds` · `favicon-metrics` · `wordmark-workshop`) under this naming; kol-brand's `logos` and `favicons` lists point at the new paths; its `svg/` keeps copies on the 30-day ledger, then empties. The thirty-odd apps here that import `kol-brand/svg/favicon-01.svg` for `AppHub`'s `logomark` switch to `kol-icons/…/kolkrabbi/kolkrabbi-logomark.svg`.
- `metrics.svg` → `metric/metric.svg`; `metrics` stays an Icon alias on the 30-day ledger (`RENAMED_ICONS`). `mirror-mir.svg` moves to `mirror/mirror-alt-mir.svg` as the 2.2 candidate, out of the Icon map.
- Acceptance: `<Icon name="mirror">`, `<Icon name="metric">`, `<Icon name="kolkrabbi">` render from the folders; `<Icon name="metrics">` renders with the rename warning; `IDENTITY` holds exactly one name per folder; every kol-brand `svg/*` path still resolves and its CHANGELOG names the new path for each.

### 1.2 — The rendered set, one script here — ✅ built 2026-10-28
- `scripts/render-identity.mjs` (sharp, root devDependency; the three apps' `generate-icons.mjs` folded into one) writes into each identity's folder from its `-logomark` and `-wordmark`: `<id>-tile.svg` + `<id>-tile-light.svg` · `apple-touch-icon-dark.png` + `apple-touch-icon-light.png` 180 (the website's `web`, `media`, `metric` ship both) · `icon-192.png` · `icon-512.png` · `icon-512-maskable.png` (mark in the middle 50 %) · `<id>-favicon.svg` · `og.svg` + `og.png` 1200×630 (the lockup-h or wordmark across the ground when the identity has one, else the mark). `pnpm identity:render`. Every identity gets every file; nothing is skipped for any of them.
- The PNGs match no glob (the Icon map takes `<id>/<id>.svg` only), so they cost install size, about 88 KB per identity, and never enter a bundle.
- Acceptance: for Mirror the rendered PNGs are pixel-identical to `kol-mirror/public/touch-icons/*.png` and `public/og/mirror.png` (same source, same sharp density), proved by a byte or pixel diff in `_tmp/2026-10-28-identity-render/`.

### 1.5 — A chunk per set — ✅ built 2026-10-28 (P: *"I cant believe you have to take every icon we ship if you only need one?"*)
- Today `iconData.js` eager-globs interface, signal and identity into ONE async chunk, so the first `<Icon>` on a website loads every signal and identity glyph too; the source comment that says a website "pays nothing for the rest" is not true as written. Three chunks, one per set, loaded when a name in that set is first asked for (the names-only index is already separate and cheap).
- Acceptance: a Vite build of `apps/identity` shows three icon chunks; a page that renders only interface names requests only the interface chunk (Playwright network log).

### 1.6 — The loader gets its name; kol-brand's folder loader retires — ✅ built 2026-10-28 (P: *"Logomark is the loader Im talking about, it just has a terrible name"*, *"VectorLoader or AssetLoader?"*)

- kol-brand's `Asset` (`@kolkrabbi/kol-brand/svg`, globs its own folder only, so it never loaded a consumer's file) retires with the SVGs on the same 30-day ledger; its README points at `VectorLoader` + the kol-icons paths. `Graphic` (kol-component's own illustrations) and `Icon` are untouched: three loaders become two, Icon for a name in a set, VectorLoader for any file.
