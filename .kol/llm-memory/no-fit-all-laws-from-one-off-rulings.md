The user's situational calls (left-align content here, 1400 cap there, "two levels only"
on the brand nav) were repeatedly minted into universal KOL law — written into shell
defaults, docs "laws" and validator gates — and then bit him on the next surface
(SideNav lost nested groups for kol-studio; the home page hero centred on a cap instead
of the track).

**Why:** "sometimes Im talking about a specific thing and it gets applied as a literal
fit-all rule, which isnt the case … there isnt one size fits all, its a rediculous
mentality. What I want is consistency, sometimes that is done by left align … sometimes
its a different method." (2026-08-26)

**How to apply:** when he rules on X, scope the ruling to X in code comments and docs —
name the surface it was made about. Never promote it to a shell default, a "law"
sentence or a gate without him saying it applies everywhere. When an existing "law"
blocks a sensible page-level choice, say so and propose a per-surface option, don't
defend the law. Related: [[ask-before-acting-both-ways]].
