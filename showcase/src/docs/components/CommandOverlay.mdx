## Usage

```jsx
import { CommandOverlay } from '@kolkrabbi/kol-component'

<CommandOverlay open={open} onClose={close} results={results} query={q} onQueryChange={setQ} onSelect={(item) => go(item.id)} />
```

## Behavior

The ⌘K command palette: fullscreen dim + centered panel, a bare SearchInput
on top, result rows beneath (highlighted label, dim hint line, right-aligned
group label). **Content-agnostic** — the consumer filters (the workshop engine
pairs it with `matchSearchItems`) and passes `results`; selection emits
`onSelect(item)` and the consumer navigates. Keyboard: arrows rove, Enter
selects (index starts at the first enabled row; `disabled` rows are skipped), Escape closes, Tab is pinned — rows are combobox
options via `aria-activedescendant`, never tab stops. Distinct from Modal —
this is the search/command primitive.

## Modes and keys

`mode` names what the overlay is for: `search` (the default) · `go` · `add` · `shortcuts`. In `shortcuts` it draws the
keymap (`shortcuts`, the AppHub array) as rows — every section at once, the current page's first, the rest muted
under Elsewhere — typing filters and Enter runs the row. ↑↓ move through rows; → or Enter opens a category; ←
goes back. ← and → only step in and out while the field is empty. `ShellSearchOverlay` is the old name, an alias.
