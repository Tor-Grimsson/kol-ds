# Media app plan

The first app in the tier. Concept and reasoning live in `~/.dotfiles/docs/operations/systems/apps-tier/INDEX.md`; the ticket that ordered the work is `lobby/inbox/apps-tier-media-first.md`. This page is the build order only.

**The goal is kol-r2b2's media app running here on fake data, with the stacked-surfaces problem fixed. Nothing else.** Development is iterative — the file-management verbs in the ticket (tags, smart folders, drag, context menus) are *direction for later*, named as examples and explicitly not a checklist to clear in one pass.

## Why

The mobile media browser took six published component versions (0.209 → 0.215) to land one screen. Two of those existed only because a prop was documented on one page and not forwarded to its sibling — something visible in seconds to anyone clicking the app, invisible to anyone reading the source.

There is nowhere in this repo to *use* a product. `showcase/` presents, `workbench/` isolates. The only surface where a product can be exercised is a consumer repo holding real credentials, so concept ownership has drifted into consumers and the media upload surface now exists twice — once in kol-r2b2, once as a fork in kol-client-olina.

## Current state

The base is **kol-r2b2**, which is the live consumer and the working version.

- `src/App.jsx` (245 lines) renders `MediaLibrary` twice — `variant="browse"` then `variant="library"` — stacked, with `UploadZone` between them. That stack is the problem to fix.
- Its client is `createMediaClient({ buckets })` plus `downloadUrl` · `deleteObject` · `renameObject` (`src/lib/client.js`). That shape is what the fixture has to satisfy.
- `UploadZone.jsx` (82 lines) is app-local and is the surface that exists twice — here and forked in kol-client-olina.
- Folders come from a **baked** manifest (`src/data/folder-tree.json`, generated by `scripts/folder-tree.mjs`), not from live state, so folder verbs have nothing to act on.
- In this repo: `packages/*` plus two loose workspaces in `pnpm-workspace.yaml`, no `apps/*`.

## Target

kol-r2b2's app, running in `apps/media` over a fake mutable tree with a **Clear changes** reset, wired per [[01-tier-rules|the tier rules]] — and browse and files as two views of one surface instead of two stacked pages.

## Phases

### 1. Tier

`apps/*` joins the workspace globs. `apps/media` scaffolded as a Vite app, `private: true` so it can never publish, depending on the packages by name. `packages/*` does not move.

Root gets `pnpm media`, mirroring the existing `pnpm workbench`. Development and testing happen there, locally, on its own port.

Media also publishes to **`ui.kolkrabbi.io/apps/media`** in the same pass, per [[01-tier-rules|the tier rules]]. That URL is a window on the last push — somewhere to open the current state from any machine — not where the work happens.

### 2. Fixture

The fake tree, its verbs, and the reset — **before any UI**. It stands in for `src/lib/client.js`, so it implements the same seams the pages already call. Files and folders as real nodes, not keys with slashes in them, which is what gives folder verbs something to act on. Session-lifetime browser memory. `showcase/src/sets/record-manager-cms.jsx` proves the shape at 165 lines.

### 3. Surface

kol-r2b2's app ported over the fixture — `App.jsx`, `UploadZone`, `KindOverview`, its settings — with `lib/api` and `lib/client` swapped for the fake. Running and clickable. This is the first time the product can be exercised without credentials.

### 4. The split

The problem raised with kol-r2b2: `LibraryHeader` renders inside both `MediaLibraryBrowse` and `MediaLibraryLibrary`, and the two are always-rendered pages stacked on each other rather than two views of one surface — which is why Upload means scrolling past a full-height browser to reach the drop zone. Fixed in the packages, with the app as the proof.

## Acceptance

- `apps/media` runs on `pnpm media`, imports by name, and is excluded from publishing.
- It is reachable at `ui.kolkrabbi.io/apps/media`, deep links included.
- No network, provider or credentials anywhere in it.
- kol-r2b2's app runs against the fixture, and its operations execute.
- **Clear changes** resets the tree to seed, repeatably.
- Browse and files are one surface, and the upload target is reachable without scrolling past a full-height browser.
- No UI component originates inside `apps/media`.

Nothing here requires a published version, and nothing requires a change in kol-r2b2.

## Excluded

**Relocating `showcase` and `workbench` under `apps/` — ruled deferred 2026-09-21** (*"we revisit that later"*). The ticket's definition of done asks for it; it is not part of this build and is not a phase. Do not re-propose it until media is done.

The file-management feature list in the ticket — tags, smart folders, drag to move, multi-select, context menus — is direction, not scope. It arrives iteratively, after the thing runs.

## Touch next

Split out of D1 on 2026-09-23 — a UI pass on the existing surface, no store behind it, so it goes first.

Nothing this round was measured below 1400 wide. Long-press opens the context menu; on `pointer: coarse`, rows and tiles get a `···` button that opens the same menu; then a pass over all three views and Quick Look at 390 and 768.

## D1

Done 2026-09-25 → 2026-09-26 (plan v2 in `.kol/llm-context/playbook/2026-09-25-d1-scope-and-plan.md`). What a database beside the bucket adds — olina's is Cloudflare D1 — as optional client verbs; the contract is written at the head of `MediaLibraryPages.jsx`, and a client without a verb hides that feature. One user, ever: no identity, no edit conflicts.

- **The imagined setup** — `apps/media-fixture`: a fake bucket and a fake D1 (tags, favourites, folder rows, an event log, smart folders, settings), rows keyed by a permanent file id so a move keeps them. Settings persist in browser storage the way a D1 row survives a reload; everything else resets with **Clear changes**.
- **Tags** — on files and folders: chips in the preview pane with suggestions from the bucket's own tags, Tags… / Add tags to N… in the menu, a Tags filter group, a Tags column under Fields. A markdown file's frontmatter tags merge into its tags on save. Settings → Tags renames a tag everywhere; renaming onto an existing one merges them.
- **Favourites** — a star in the pane and the menu, on files and folders; a Favourites filter group.
- **Recents** — the event log (opened · edited · created · uploaded), shown on Home.
- **Smart folders** — saved queries (tags · kinds · text) as chips above the body; a chip shows its matches flat.
- **Documents** — `DocumentEditor`: New document (name + type), a fields form over a markdown file's frontmatter, Write / Split / Preview, Attach from the bucket, SVG as text with its picture, a 1 MB cap. **Drafts are browser memory** (`utilities/localDrafts`), never the database's; a draft newer than the file is restored, and it follows a rename or move.
- **Personalisation** — view settings load and save through the client when the page is uncontrolled.
- **apps/media-shell** — Home (Recent · Favourites · Smart folders · Unsaved drafts · Tags), Browse, Settings (Preferences · Tags · Shortcuts · About), the first-run tour.
